# N2_web — Deep Audit & Improvement Roadmap

> Audit 12 subsystems with 12 parallel read-only agents, then adversarially verified
> every high/critical finding through 2 independent refuters (correctness + product impact).
> A finding counts as CONFIRMED only if both refuters failed to refute it.

**74 raw findings -> 28 verified -> 15 confirmed, 13 refuted, 46 unverified leads.**

## Executive summary

N2_web là PWA vanilla ES modules với nền tảng dữ liệu sách giáo trình tốt (233 bài, 1899 câu), Edge Functions cách ly Gemini và RLS theo hướng đúng; kiến trúc không cần viết lại. Bốn nhóm rủi ro đã được xác minh cần xử lý theo thứ tự: (1) mất dữ liệu offline — `js/app.js:228-230` gọi `pullFromCloud` trước `flushCompletionQueue`/`flushReviewQueue`, còn sign-out tại `js/profile-page.js:126-127` xoá queue chưa sync không cảnh báo; (2) lệch dữ liệu giáo trình — `scripts/classify-questions.mjs:58` đánh số Q1..Qn khiến 111 bài mang index 1-based, và `scripts/finalize-book-data.mjs:61-68` có thể xoá sạch `enrichmentFiles` khỏi `manifest.json`; (3) bảo mật — Gemini API key từng commit vào repo public, RLS `user_profiles` cho client UPDATE mọi cột kể cả `streak`/`total_study_ms`; (4) code production pha phiên bản — 107/120 relative import không có `?v=33` nên Service Worker cache-first có thể trộn module graph. Đề xuất: quick win 1-2 buổi cho nhóm (1)(2)(3) và giảm app shell 13.6MB skin; strategic cho cache-busting tự động, migration tracking, và timeout Gemini phía client. Không đưa React, bundler hay monorepo vào bất kỳ mục nào.

## What is already strong (do not disturb)


- Pure ES modules, không framework, không bundler cho app core: ranh giới nhỏ, deploy tĩnh lên Vercel đơn giản, hợp solo maintainer.
- Học engine core tách pure function (`js/learning-engine.js`) và có unit test cho happy path + SRS.
- Backend cách ly đúng: SECURITY DEFINER RPC, chấm điểm server-side qua `exam-review`, `exam-fetch` strip exam content, Gemini chỉ đi qua Edge Function với multi-key fallback chain.
- Offline mutation queue (`js/completion-service.js` pattern) là hướng đúng; chỉ cần sửa thứ tự flush.
- Ownership model RLS `auth.uid() = user_id` nhất quán; chỉ cần thu hẹp cột được UPDATE chứ không cần viết lại policy.
- CSP không cho inline script, typography/token theo `docs/DESIGN_TYPO.md`, `prefers-reduced-motion` áp dụng cả CSS và rAF loop pet, modal có focus trap + scroll lock.
- Audio host qua GitHub Release (0 phí storage), CSP `media-src` cho `*.githubusercontent.com`.
- 154/154 unit test pass (~9.6s) với coverage tốt cho schema invariant và pure math.

## Quick wins (Phase 0-1)

### 1. Giữ tiến độ offline qua sync và sign-out  
**Effort:** S | **Impact:** high  
**Why:** Learner offline tick bài rồi mở app có mạng sẽ mất done-flag tạm thời; nếu tab đóng trước khi flush xong thì mất vĩnh viễn. Sign-out hiện xoá queue chưa sync mà không warning.  
**Change:** js/app.js:226-231 đổi thứ tự thành `await flushCompletionQueue(authedUser.id); await flushReviewQueue(authedUser.id); await pullFromCloud(authedUser.id);`. Trong js/sync.js `pullFromCloud` merge thay vì replace: `const map = { ...readProgressMap(), ...remoteMap }` (export `readProgressMap` từ js/store.js). js/profile-page.js:126-130: capture user trước `signOut()`, flush hai queue, chỉ gọi `clearUserScopedStorage()` khi queue rỗng; còn sót thì hiện warning và abort sign-out.

### 2. Thu hồi và scrub Gemini API key đã lộ trong git history

Trước khi revoke rộng, chuyển legacy migration `LEGACY_KEYS.n2_streak_v2` trong js/sync.js sang gọi RPC server.

### 6. Không precache 13.6MB skin option trong app shell  
**Effort:** S | **Impact:** high

### 7. Giữ đúng một lần phát listening trong mock exam

## Strategic (Phase 2-3)

### 1. Tự động hoá cache busting và phát hiện SW update  
**Effort:** M | **Impact:** high  
**Why:** 107/120 relative import không có `?v=33`; SW match theo full URL nên deploy bump entry point vẫn có thể phục vụ module cũ cho tới navigation sau, tạo module graph pha phiên bản.  
**Change:** Tạo `scripts/bump-version.mjs` thay đồng bộ `?v=N` trong index.html, sw.js, css/styles.css và các import entry. Mở rộng tests/pwa-security.test.mjs:24-47 để assert mọi relative import trong js/*.js mang cùng `?v=N` với `CACHE_NAME`; fix các import thiếu. Trong sw.js activate gửi `{type:'SW_UPDATED'}` tới clients và js/app.js reload khi nhận message.

### 2. DB migration tracking và rollback đầy đủ  
**Effort:** M | **Impact:** medium  
**Why:** Hiện apply schema thủ công, không version marker; rollback file duy nhất chỉ tương thích migration 18/08 trong khi migration sau đã drop cột và đổi chữ ký get_leaderboard.  
**Change:** Thêm bảng `schema_migrations(version, applied_at)` và cho scripts/apply-schema.mjs ghi version khi chạy. Thêm CI step so `supabase/schema.sql` với tổng hợp `supabase/migrations/*.sql` và fail nếu lệch. Viết rollback SQL cho 20260818190000, 20260821120000, 20260822090000, 20260822120000 theo convention `supabase/rollback/`, trong đó 20260821120000 phải khôi phục các cột đã drop và `get_leaderboard` cũ.

### 3. Giảm thời gian treo Gemini xuống mức client kiểm soát được  
**Effort:** M | **Impact:** medium  
**Why:** 4 model × 45s cho phép một lượt chat treo tới ~3 phút; UI hiện 'Đang soạn câu trả lời…' với input disabled mà không có nút hủy, và lỗi 429 làm mất nội dung người dùng vừa gõ.  
**Change:** Trong supabase/functions/_shared/gemini-models.js hạ `REQUEST_TIMEOUT_MS` xuống ~25s nhưng giữ nguyên độ dài chain; `js/gemini.js` `callGeminiProxy` thêm `AbortController` 15s; js/tutor.js và js/voice.js phân biệt lỗi 429 quota với lỗi auth, giữ draft message và hiện nút Thử lại.

### 4. Hợp nhất counters review cross-device thay vì last-write-wins  
**Effort:** M | **Impact:** medium  
**Why:** Device B sync một item review vài giây sau sẽ wipe attempts/lapses của Device A; chỉ mất aggregate counters nhưng làm undercount weakness, và push lại thừa mỗi lần login.  
**Change:** Trong js/review-sync.js `mergeReviewCollections` giữ record mới nhất cho `intervalDays`/`dueAt` nhưng reconcile counters qua một RPC merge server-side (GREATEST cho attempts/correctAttempts/lapses) hoặc per-device revision watermark. Không cộng thẳng ở client để tránh double-count mỗi lần pullFromCloud.

### 5. E2E auth-aware cho vòng học end-to-end  
**Effort:** M | **Impact:** medium  
**Why:** 11/12 Playwright test xoá auth modal bằng DOM surgery nên auth gate, token refresh và cross-tab/cloud sync chưa từng chạy trong browser.  
**Change:** Trong tests/e2e/app.spec.mjs thay `dismissAuthGateForComponentChecks` bằng mock Supabase session/auth token provider, thêm flow: làm quiz -> trả sai -> kiểm tra review row local và remote -> tới hạn -> mini-test -> readiness cập nhật. Nếu OAuth thật không mock được trong hermetic run, giữ nguyên component smoke tests và bổ sung integration test cho review-sync.

## Do not do


- Không viết lại app thành React/Vue, không thêm bundler hay monorepo: ES modules + Vercel static đủ cho quy mô hiện tại, chi phí migration vượt xa lợi ích.
- Không tiếp tục bump `?v=33` bằng tay thêm lần nữa: cách đó đã bị quên ở commit b3d6a75 và SW vẫn phục vụ module cũ tới lần bump kế tiếp.
- Không mô tả cache-first là làm mất app "vĩnh viễn": activate event xoá cache cũ theo `CACHE_NAME`; rủi ro thực tế là module graph pha phiên bản trong cùng một deploy.
- Không `REVOKE UPDATE` toàn bảng `user_profiles`: sẽ phá `pushProfile` (js/sync.js) và legacy migration `n2_streak_v2`; chỉ chặn cột `streak`, `last_study_date`, `total_study_ms`.
- Không cộng thẳng `attempts`/`lapses` ở client trong `mergeReviewCollections`: sẽ double-count mỗi lần pullFromCloud và có thể vi phạm CHECK constraint của schema.
- Không cắt chain model xuống 2 model hoặc hạ timeout server xuống 8-10s: 429 trả về tức thì, timeout cắt ngắn sẽ bỏ sót câu trả lời chậm hợp lệ; ưu tiên `AbortController` phía client.
- Không đưa 2.3MB JSON sách hay 519MB ảnh vào `APP_SHELL`: `cache.addAll` fail atomic và tốn băng thông; runtime stale-while-revalidate ở sw.js:55-61 đã đủ.
- Không "làm lại toàn bộ" test suite vì thiếu coverage: ưu tiên behavior test cho luồng auth/sync; test regex trên source string giữ nguyên, chỉ bổ sung khi logic đổi.
- Không sửa `get_leaderboard` hay cấu trúc DB bảng lớn; blast radius của các finding backend đều hẹp, sửa grant/trigger là đủ.

## Refuted (do NOT work on these)

- **Cache-busting ?v=33 thiếu trên 106/118 internal imports, APP_SHELL thiếu toàn bộ view chính**  
  Verified: 1) sw.js:2-29 APP_SHELL contains only 10 JS files (app.js?v=33, pet*.js?v=33, kanji-writing.js?v=33, viewport-fit.js?v=33, profile-avatar.js, vendor/supabase.js) - zero route views (dashboard, lesson, tutor, voice, exam, leaderboard, review, profile-page) and core modules (store, router, sync, learning-state) are in APP_SHELL. 2) grep -rn "from '\./" js/ returns 118 imports, only 12 use ?v=33, 106 are unversioned. 3) vercel.json has no Cache-Control header config for .js files. 4) sw.js:55-61 fetch handler caches on-the-fly via caches.match(request) || fetch, but cold offline start cannot render any view module not pre-cached in APP_SHELL. Deploy updates fail to bust browser HTTP cache for unversioned imports.

- **Service Worker precaches 13.7MB of optional pet skin textures on every PWA install**  
  Inspected sw.js:19-26 and measured disk sizes. APP_SHELL lists 8 skin textures (1.26MB-1.91MB each, sum 13.08MB out of 15.63MB total shell). Default pet settings in js/pet.js:29 use 'classic' skin which references base atlas, not these skins. sw.js:31-34 calls cache.addAll(APP_SHELL), which fails atomically if any single asset download fails, blocking PWA installation.

- **Boot loads and parses the entire 2.3MB book curriculum before anything renders**  
  Re-read js/app.js:122-150, 181-182, 262-288 and js/router.js:100-161. The load behavior is exactly as described: loadBookContent() reads data/book/manifest.json, takes every category `file` (the manifest has no `files` array, verified: `Array.isArray(m.files) === false`), fetches all 5 in Promise.all (app.js:132-136), then loadEnrichment fetches every category's classification/images/vietnamese (app.js:152-179). Measured with node over the manifest: exactly 18 files fetched, 2.24MB raw (2.29MB counting manifest), 430KB gzipped; per category kanji 717KB, vocabulary 766KB, grammar 508KB, reading 212KB, listening 88KB — matching the evidence. Call is unconditional at app.js:283 (`void loadBookContent()`), not gated by route, so even a #/tutor or #/exam landing pulls the whole corpus.

But the headline "before anything renders" is refuted by the surrounding code: bootstrap awaits only loadLessons() (data/lessons.json, 55KB) at app.js:265, then initRouter() renders synchronously (app.js:269-281) BEFORE loadBookContent is even invoked at line 283. loadBookContent is `void`ed, so it is non-blocking, and the code comment at app.js:262-264 states this intent explicitly. The dashboard builds its search index from lessons.json with a possibly-empty getBookContent (dashboard.js:225, store.js:147-149) and is repainted once when content lands (app.js:287, guarded by BOOK_CONTENT_ROUTES). sw.js:55-61 is cache-first/stale-while-revalidate for same-origin GETs, so repeat visits read the 18 payloads from the service-worker cache rather than the network. The only case where content genuinely gated rendering is a cold deep link to #/lesson/<id>, where renderLesson paints with null bookContent (lesson.js:642-654) and the full body appears only after the burst; but lessons.json is already indexed, so no route is blank and FCP is not blocked. Also, the same-app shell statically imports ~40 modules regardless, so the "on top of 42 already-parsed JS modules" framing is not a distinct cost.
